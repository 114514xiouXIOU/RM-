# 重投影算例（带旋转）—— 专门用来检验"旋转矩阵方向 / 转置有没有搞反"
#
# 本算例：R = 绕世界 Z 轴旋转 +90°，t = (0, 0, 0)
#   Pc = R * Pw，所以相机就架在世界原点、朝 +Z 方向看，只是"歪着头"转了 90°。
#
# 旋转矩阵（行优先，直接填进输入文件）：
#       [  0  -1   0 ]        Rz(90°) 把世界 +X 轴转到相机的 +Y 方向，
#   R = [  1   0   0 ]        把世界 +Y 轴转到相机的 -X 方向。
#       [  0   0   1 ]
#
# 逐点手算（Pc = R * Pw）：
#   点1：Pw=(1000, 0, 1000) -> R*Pw = (0, 1000, 1000)
#        u = 800*0/1000 + 640    = 640.000
#        v = 800*1000/1000 + 360 = 1160.000     -> 超出 720 高度，在画面外
#   点2：Pw=(0, 1000, 1000) -> R*Pw = (-1000, 0, 1000)
#        u = 800*(-1000)/1000 + 640 = -160.000  -> 左边出画
#        v = 800*0/1000 + 360       = 360.000
#   点3：Pw=(0, 0, 1000) -> R*Pw = (0, 0, 1000)   （光轴上的点，不受 Z 轴旋转影响）
#        u = 640.000, v = 360.000               -> 画面正中心
#
# 期望结果（观测值故意各偏 0.1，所以误差 = sqrt(0.1^2 + 0.1^2) = 0.1414）：
#   点1 -> (640.000, 1160.000)，误差 0.1414 px，画面内 = 否
#   点2 -> (-160.000, 360.000)，误差 0.1414 px，画面内 = 否
#   点3 -> (640.000, 360.000)， 误差 0.1414 px，画面内 = 是
#
# 把 R 转置一下（第 2、4 个数的符号反过来）再跑，点1 和点2 的结果会互换 ——
# 这就是"旋转方向搞反"的典型症状。
