# 重投影计算（C++17）

输入三维世界点、相机内参与已知外参，按理想针孔模型（忽略畸变）计算二维像素坐标，
并给出与对应观测点之间的像素欧氏距离（重投影误差）。

## 坐标系约定

- 外参为世界到相机的变换：`Pc = R * Pw + t`
- 三维坐标与平移量使用相同长度单位
- 相机坐标系：X 向右、Y 向下、Z 向前（光轴指向 +Z）
- 像素坐标系：原点在图像左上角，`u` 向右增大，`v` 向下增大
- `Zc <= 0`（点在相机平面上或相机后方）判为无效，不参与统计

## 目录结构

```
.
├── CMakeLists.txt
├── include/
│   ├── camera.h            数据类型与坐标变换接口
│   └── reprojection.h      重投影与误差评估接口
├── src/
│   ├── camera.cpp          坐标变换实现
│   ├── reprojection.cpp    重投影与误差实现
│   └── main.cpp            输入解析、逐点计算、结果输出
└── data/
    ├── sample_no_rotation.txt   测试数据 1：无旋转
    └── sample_rotation.txt      测试数据 2：绕 Z 轴 90°
```

## 构建与运行

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/reproject data/sample_no_rotation.txt
./build/reproject data/sample_rotation.txt
```

不使用 CMake 时也可直接编译：

```bash
g++ -std=c++17 -Wall -Wextra -O2 -Iinclude src/camera.cpp src/reprojection.cpp src/main.cpp -o reproject
```

> `-G Ninja` 用于指定 Ninja 作为构建后端。若系统已安装 `make`，可省略该参数。

## 两种运行模式

### 文件模式：从数据文件读入

```bash
./build/reproject data/sample_no_rotation.txt
```

一次计算文件中所有点，最后以表格形式输出每个点的结果与统计信息。

### 交互模式：逐步提示输入

```bash
./build/reproject
```

不带参数运行时进入交互模式，程序会逐项提示输入内参、外参，然后反复提示输入三维点，
每输入一个点立即给出该点的相机坐标、深度、投影结果与像素误差。要点：

- 相机参数输入完成后会打印一次配置摘要，便于核对
- 输入非法内容（例如 `abc`）会提示重试，不会中断程序
- 在 `Xw` 处输入 `q`（或按 Ctrl+Z 回车）结束录入并输出统计
- 图像宽高填 0 表示不做"是否出画"的检查

交互模式采用 `std::stod` 解析输入并捕获异常，
因此 `u=5` 这类带前缀的写法不会导致程序崩溃或产生错误结果，而是提示重新输入。

## 输入格式

```
num_points
fx fy cx cy width height
r00 r01 r02
r10 r11 r12
r20 r21 r22
tx ty tz
Xw Yw Zw u_obs v_obs        (重复 num_points 行)
```


## 输出说明

逐点输出相机坐标 `Pc`、重投影像素、观测像素、深度 `Zc`、像素误差以及是否落在画面内；
`INVALID` 表示该点因 `Zc <= 0` 被判为无效投影。末行给出有效点数、平均误差、RMSE 与最大误差。

## 测试数据与期望结果

**测试数据 1**：`fx = fy = 800`，`cx = 640`，`cy = 360`，`R` 为单位矩阵，`t = (0, 0, -1000)`

| 点 | 世界点 Pw | 相机点 Pc | 重投影像素 | 观测像素 | 误差 (px) |
| --- | --- | --- | --- | --- | --- |
| 1 | (0, 0, 1000) | (0, 0, 0) | 无效（`Zc = 0`） | (640, 360) | — |
| 2 | (0, 0, 2000) | (0, 0, 1000) | (640.0000, 360.0000) | (640, 360) | 0.0000 |
| 3 | (100, 50, 3000) | (100, 50, 2000) | (680.0000, 380.0000) | (680.5, 385.5) | 5.5227 |
| 4 | (0, 0, 500) | (0, 0, -500) | 无效（`Zc < 0`） | — | — |

汇总：有效点 2 个，平均误差 2.7613 px，RMSE 3.9051 px，最大误差 5.5227 px。

**测试数据 2**：绕世界 Z 轴旋转 90°，`t = (0, 0, 0)`

| 点 | 世界点 Pw | 相机点 Pc | 重投影像素 | 误差 (px) | 画面内 |
| --- | --- | --- | --- | --- | --- |
| 1 | (1000, 0, 1000) | (0, 1000, 1000) | (640.0000, 1160.0000) | 0.1414 | 否 |
| 2 | (0, 1000, 1000) | (-1000, 0, 1000) | (-160.0000, 360.0000) | 0.1414 | 否 |
| 3 | (0, 0, 1000) | (0, 0, 1000) | (640.0000, 360.0000) | 0.1414 | 是 |

汇总：有效点 3 个，平均误差 = RMSE = 0.1414 px。

## 异常情况处理

- **深度非正**：`Zc <= 0` 时直接判为无效并返回，不执行透视除法。
  若忽略该检查，`Zc < 0` 会使相机后方的点被翻折到画面前方，产生看似正常但错误的像素坐标。
- **阈值取 `1e-9`**：浮点运算可能得到极小的正深度，除以它会得到量级异常的结果，
  因此采用"小于极小阈值"而非直接判断 `<= 0`。
- **输入格式错误**：内参、外参或点数据读取失败时输出错误信息并以非零码退出。
- **交互模式下的非法输入**：用 `std::stod` 解析并捕获 `std::invalid_argument` / `std::out_of_range`，
  非法输入只提示重试，不会中断程序，也不会把无效值带入计算。
  记录输入进度所需的状态保存在函数外的变量中，因此重试时不会丢失已输入的内容。
